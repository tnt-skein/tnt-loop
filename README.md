# tnt-loop

Периодический цикл на фибере для Tarantool: такт, пауза до следующего,
пробуждение сразу при остановке или толчке, защита от падения такта —
и у каждого такта своя область контекста со своим `request_id`.

```lua
local loop = require('tnt.loop')

local poller = loop.new({
    name = 'cluster_poller',   -- имя фибера
    interval = 5,              -- период в секундах, от начала такта
    tick = poll,               -- что делать на такте
    on_error = report,         -- упавший такт: текст ошибки
})

poller:start()   -- первый такт — сразу, следующие — раз в пять секунд
poller:wake()    -- такт вне очереди: пауза прервана
poller:stop()    -- будит паузу и кончает цикл, не дожидаясь периода
```

Зависимости: `tnt-context` (область такта), `tnt-id` (опознаватель
такта) и `tnt-must` (проверка настроек).

## Зачем

Цикл «сделать, подождать, повторить» пишут заново в каждом пакете,
которому нужно наблюдение, и в каждом он ошибается по-своему: период
растёт вместе с временем такта, остановка ждёт целый период, исключение
молча убивает фибер, перезапуск без уступки оставляет два фибера, записи
такта нечем связать между собой, а ошибка в настройках прячется в фибере.
Пакет делает шесть вещей:

- **Пауза от начала такта**, по времени планировщика: период не растёт
  вместе с временем такта и не съедается работой без уступки. Такт дольше
  периода даёт следующий сразу.
- **Остановка и толчок будят паузу сразу.** `stop` возвращается тут же;
  `wake` начинает следующий такт немедленно, толчок во время такта
  не теряется, толчки не копятся.
- **Такт под защитой.** Упавший отдаётся `on_error` текстом, цикл живёт
  дальше; бросок самого `on_error` цикл тоже переживает.
- **Область на каждый такт** с новым `request_id` — ULID: записи одного
  такта связаны, запись о падении несёт номер упавшего такта, контекст
  запустившего цикл в такты не попадает.
- **Один фибер на цикл.** Остановка и запуск без уступки между ними
  не оставляют прежний фибер жить рядом с новым.
- **Настройки проверяются при сборке.** Имя, такт, период и обработчики
  не того вида, как и незнакомый ключ, — бросок на строке вызывающего,
  а не молчащий фибер.

## Установка

```sh
tt rocks install tnt-loop --server=https://tnt-skein.github.io/rocks
```

Или из исходников:

```sh
git clone https://github.com/tnt-skein/tnt-loop.git
cd tnt-loop && tt rocks make
```

## Как пользоваться

| Вызов | Что делает |
|---|---|
| `loop.new(opts)` | собирает цикл; `name`, `tick` обязательны, `interval` по умолчанию 5, `on_error`, `on_stop`, `scheduler_now` — по желанию; настройки не того вида и чужой ключ — бросок на строке вызывающего |
| `:start()` | запускает; первый такт — сразу; повтор у идущего цикла — ничего |
| `:stop()` | останавливает: будит паузу, зовёт `on_stop`; такта не ждёт; повтор — ничего |
| `:wake()` | такт вне очереди; во время такта — следующий без паузы; толчки не копятся; остановленному — ничего |
| `:running()` | идёт ли цикл |
| `:set_interval(seconds)` | новый период с паузы после следующего такта; `nil` — умолчание; ноль и меньше — без паузы; не число — бросок |

```lua
loop.new({ name = 'cluster_poller', tick = 'poll' })
--> app/poller.lua:12: настройки цикла.tick — функция или вызываемая таблица, а не строка
```

Такт идёт под `pcall`: упавший отдаётся `on_error` одной строкой,
в области упавшего такта, и цикл делает следующий такт через период.
Без `on_error` цикл тоже выживает — падение остаётся незамеченным.
`on_error` зовётся под своим `pcall`: его бросок фибер не убивает,
но и сказать о нём некому, поэтому обработчику положено не бросать.

```lua
local context = require('tnt.context')

local walker = loop.new({
    name = 'walker',
    interval = 60,
    tick = function()
        context.get(context.REQUEST_ID)   -- ULID, свой у каждого такта
    end,
})
```

Контекст того, кто позвал `start`, в такты не переносится, а между
тактами области нет. Операцию мельче такта владелец заводит вложенной
областью `context.run` сам: её ключ ложится поверх тактового.

Часы вынесены в настройку `scheduler_now` ради проверок: цикл
с подставленными часами проверяется без ожидания.

## Проверки

```sh
make deps          # luatest, luacheck, luacov с cluacov и зависимости пакета в .rocks
make check         # форматирование, линт, проверки, покрытие с порогом 100 %
make mutants-all   # мутационное тестирование утилитой tnt-mutants из PATH, порог 100 % убитых
```

Покрытие строк — 100 %, убитых мутантов — 100 % (44 проверки, 45 мутантов
в одном модуле). Арифметика паузы проверяется на часах, которые
двигает сама проверка; остановка, толчок, падение такта и перезапуск
без уступки — на настоящих фиберах с ожиданием; отказы настроек —
текстом и местом броска.
